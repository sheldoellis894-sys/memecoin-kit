## Подробно

### 1. Лимит трат ИИ у Chef Rekt (A06:2025 Insecure Design, CWE-799)
- Где: `templates/landing/api/inspect.js`, функция `allow()` (строки 18–37) и проверка Origin (строки 47–49)
- Что: лимит «5 инспекций в день с адреса, 300 в день всего» хранится в `Map` в памяти одной копии функции (в коде так и написано: «a brake, not a wall»). На Vercel копий может быть несколько, и каждая новая начинает счёт с нуля. Проверка Origin срабатывает только если заголовок Origin есть, а скрипт может его не присылать
- Путь: `POST /api/inspect` с любым адресом кошелька → агент вызывает модель (`LLM_API_KEY`) и Helius
- Чем грозит: кто-то в цикле с разных адресов сжигает баланс модели и лимит Helius. Сейчас ущерб ограничен депозитом 2 доллара: ключ просто перестанет работать
- Исправление: (1) лимит у поставщика модели — выставляете вы в его кабинете; (2) счётчик в общем хранилище (Upstash Redis или Blob), а не в памяти: на адрес в день и общий в день; (3) отказ, если нет Origin или он чужой

### 2. Уязвимые зависимости шаблона (A03:2025 Software Supply Chain Failures, CWE-1395)
- Где: `templates/landing/package-lock.json`, `npm audit --omit=dev`: 6 high, 1 moderate
- Пакеты: `@vercel/blob` → `@vercel/oidc` → `@vercel/cli-config` → `zod` (переполнение памяти при проверке больших коллекций); `undici` (переполнение памяти в разборе EventSource, обход SRI); `vite` (`launch-editor`, только режим разработки на Windows); `astro` (XSS через динамические имена тегов, чтение файлов через image endpoint `@astrojs/node`)
- Чем грозит на деле: часть — только при разработке (vite), часть — в коде, который мы не используем (динамические имена тегов, `@astrojs/node`, EventSource). Реальный путь атаки для наших сайтов не найден, но держать известные уязвимости в коде, который отдаём заказчику, нельзя: у Ullu заказчик уже видел предупреждение npm
- Исправление: `npm update astro vite undici` в `templates/landing`, пересобрать и проверить сайты; для `@vercel/blob` поставить версию, где цепочка `zod` исправлена (npm предлагает 2.4.0 — это откат, сначала проверить новые версии). После обновления — `npm audit` ещё раз

### 3. Пароль админки Mr. MA без проверки длины (A07:2025 Authentication Failures, CWE-521)
- Где: `server/index.mjs`: `CFG.admin = process.env.ADMIN_PASSWORD`, проверка длины только в списке предупреждений (`CFG.admin.length < 12`)
- Что: сервер запускается с любым паролем, хоть из 4 символов. Защита от подбора — 8 попыток в минуту с одного адреса, с многих адресов можно подбирать дальше
- Сравнение: у Ullu админка не включается, пока пароль короче 16 символов и в нём меньше 8 разных знаков — так и нужно
- Исправление: при старте отказываться работать с паролем короче 16 символов (как у Ullu); в README для GuruFun прямо написать требование
- Что проверить: какой пароль сейчас стоит в превью Vercel и какой поставит заказчик

### 4. Улица Ullu на Vercel: потеря записей (A06:2025, CWE-362)
- Где: `api/_agent/store.js` `serial()` — очередь только внутри одного процесса; `api/street.js`, `api/admin.js` читают и переписывают весь `street.json`
- Что: на Vercel две копии функции могут одновременно прочитать файл и записать каждая свою версию. Тогда пропадёт либо новый дом, либо бан модератора (забаненный вернётся). Там же в памяти копии хранятся использованные ответы проверки браузера и лимиты новых домов: в другой копии их можно повторить
- Где это важно: только на превью Vercel. На сервере заказчика один процесс Node, и очередь работает
- Исправление: в README передачи явно записать «только один процесс»; для Vercel — блокировка в Redis, как у Mr. MA в `api/hc.js`

### 5. Хранилище Blob по умолчанию открытое (A02:2025 Security Misconfiguration)
- Где: `api/_agent/journal.js`: `accessOf = env.BLOB_ACCESS === 'private' ? 'private' : 'public'`; файлы пишутся с `addRandomSuffix: false`, то есть по предсказуемому пути (`ullu/street.json`, `ullu/stats.json`)
- Что: если в новом проекте забыть `BLOB_ACCESS=private`, файл улицы с журналом модератора (в нём адреса IP модератора) и списком банов становится доступен по прямой ссылке
- Сейчас: у `theullu` и `thehorocope` переменная `BLOB_ACCESS` задана (значение не читалось, по записям проекта это `private`)
- Исправление: поменять умолчание на `private` и включать `public` только явно

### 6. Секрет расписания в адресе (Horocope)
- Где: `api/issue-run.js`: секрет берётся из заголовка или из `?key=`; сравнение `given === secret`
- Что: секрет в адресе попадает в историю браузера и журналы; обычное сравнение строк в теории даёт подбор по времени ответа (на практике почти невозможен)
- Сейчас: `CRON_SECRET` на `thehorocope` задан, расписание Vercel передаёт его заголовком
- Исправление: сравнивать через `timingSafeEqual` хэшей (как в `admin.js`), ручной запуск делать через заголовок, а не адрес

### 7. Гостевые голоса в превью Mr. MA (информационно)
- Где: `castVote()`, карта `guestIps` в памяти
- Что: «не больше 20 гостей с одного адреса за ход» на Vercel считается в каждой копии функции отдельно, так что накрутить гостевые голоса в превью можно сильнее
- Почему информационно: в боевом режиме голосуют только кошельки с подписью и проверкой баланса в двух снимках, гостей нет; боевой режим на Vercel вообще выключен

## Что проверено и в порядке
- Ключи и секреты в коде: не найдено (поиск по шаблонам ключей OpenAI/Anthropic, AWS, приватных ключей, Helius, GitHub)
- Переменные Vercel у `theullu`, `mr-ma`, `thechefrekt`, `thehorocope` помечены как секретные (sensitive), Vercel не показывает для них проблем
- Подпись кошелька Mr. MA: текст привязан к адресу сайта, кошельку и сроку, проверка ed25519; в боевом режиме без `SITE_HOST` места не выдаются
- Голос в боевом режиме: баланс на момент голоса и при закрытии, перевод токенов между кошельками голос не умножает
- XSS: имена домов Ullu и надписи на вывесках фильтруются (`NAME_RE`, `cleanSign`) и экранируются при выводе в SVG; админка Mr. MA экранирует данные, CSP без inline-скриптов
- Выход за папку при раздаче файлов: защищён и в `serve.mjs`, и в `server/index.mjs`
- Размер запросов ограничен, медленные клиенты обрываются по таймауту
- Админка Ullu: пароль от 16 символов, сравнение за постоянное время, журнал действий модератора
- Админка Mr. MA на Vercel: счётчик неверных паролей в Redis, общий для всех копий функции

## Что не проверялось
- Настоящий взлом работающих сайтов (для этого нужен Shannon на копии сайта, см. `docs/security-plan.md`)
- Сервер заказчика (nginx, TLS, права файлов) — его ещё нет
- Поведение Solana RPC и кошельков в браузере
- Остальные сайты шаблона без серверных функций (Molty – Ten Keys): у них нет ввода данных на сервер
- Юридические вопросы (политика данных, GDPR) — нужен юрист

# Как штамповать сайт

Один код — много сайтов. Сайт складывается из трёх файлов: конфиг проекта, тема и макет.
Код шаблона при этом не меняется. Меняется он только тогда, когда нужна новая секция или новая игра.

## Новый сайт за шесть шагов

1. **Папка проекта.** Создать `projects/<имя>/brand/` с подпапками `docs`, `references`, `logo`, `banners`, `exports`, `gallery`, `stickers`, `video`.
2. **Картинки.** Разложить по подпапкам. Имена: маленькие латинские буквы, цифры и `_`, одно расширение.
3. **Конфиг.** Скопировать `project.config.json` из похожего проекта и заменить тексты, ссылки и пути к картинкам.
   Для сайта с игрой «выбери клетку» брать за основу `projects/molty`, с бегом — `projects/tsc3000`, для сайта-документа с игрой «лови еду» — `projects/fch`, для сайта-приложения с игрой «затормози у двери» — `projects/goosini`, для сайта-станка с генератором мемов вместо игры — `projects/inkmaxx`, для сайта-двери с калькулятором долей — `projects/tenkeys`, для сайта-гида с агентом — `projects/chefrekt`, для сайта-колеса с агентом по расписанию — `projects/horocope`.
4. **Тема и макет.** В конфиге указать `"theme"` и `"layout"`. Нужен новый стиль — скопировать файл темы, поменять цвета и шрифты.
5. **Проверка.** В `templates/landing`:
   `$env:PROJECT="<имя>"; npm run dev -- --host 127.0.0.1` → открыть `http://127.0.0.1:4321`.
6. **Публикация.** `git add -A`, `git commit`, `git push`. На Vercel: новый проект из того же репозитория,
   Root Directory `templates/landing`, переменная `PROJECT=<имя>`. Имя проекта на Vercel задаёт адрес сайта.

## Что настраивается в теме

```json
{
  "name": "sunset",
  "flavor": "arcade",
  "colors": { "bg": "", "surface": "", "text": "", "muted": "", "primary": "", "onPrimary": "", "secondary": "", "accent": "" },
  "fonts": {
    "heading": "Press Start 2P",
    "body": "VT323",
    "googleFonts": "family=Press+Start+2P&family=VT323",
    "headingScale": 0.55,
    "headingMin": ".75rem",
    "headingLeading": 1.45,
    "bodyScale": 1.375,
    "ticker": "heading"
  },
  "radius": { "button": "0px", "card": "0px" }
}
```

- `flavor` — готовый характер оформления. Сейчас их шесть: `arcade` (игра 16 бит), `paper` (бумага на столе, работает вместе с макетом `contract`), `app` (приложение на экране телефона, работает вместе с макетом `delivery`), `press` (оттиск в две краски, работает вместе с макетом `press`) `vault` (бетон, сталь и чертежи, работает вместе с макетом `vault`) и `guide` (печатный гид: двойные линейки, зерно, звёзды, работает вместе с макетом `guide`). Без этого поля тема выглядит как `mine`.
- `fonts.hand` — рукописный шрифт для приписок красной ручкой (только `paper`).
- `fonts.mono` — моноширинный шрифт для цифр, адресов и строки состояния (только `vault`).
- `headingScale` — уменьшает заголовки, если шрифт очень широкий. `bodyScale` — увеличивает основной текст, если шрифт мелкий.
- `ticker` — каким шрифтом набран `$ТИКЕР`: `heading` или `body`. Правило: тикер целиком одним шрифтом, иначе знак `$` выбивается.

## Что настраивается в конфиге помимо текстов

| Поле | Зачем |
|---|---|
| `shortName` | Короткое имя для шапки, если полное длинное |
| `ui` | Подписи над разделами и значок-разделитель: `icon` (символ) или `iconImage` (картинка) |
| `boot` | Строки экрана загрузки и текст кнопки (секция `boot`) |
| `chase` | Игра-бег: спрайты, подписи, текст для поста в X |
| `feed` | Игра «лови еду»: три позы героя, еда с очками, плохие предметы, длина раунда, подписи, текст для поста в X |
| `stop` | Игра «затормози у двери»: пять картинок (едет, тормозит, ест, проехал мимо, дверь), подписи, тексты итога, текст для поста в X |
| `app` | Все подписи и данные макета `delivery`: статусы заказа, уведомления, вкладки, карта, чат, оценка, чек, истории, свайп для покупки |
| `press` | Все подписи и данные макета `press`: меню, счётчик тиража, этапы пути листа, реплики тренера, уровни краски, расписание смен, печать кнопки покупки |
| `studio` | Станок для мемов: готовые основы, наклейки, сколько наклеек открыто всем, подпись в углу листа, все подписи кнопок, текст для поста в X |
| `vault` | Все подписи и данные макета `vault`: список замков, меню, строка состояния, три цифры, колонки «всем и держателям», стойка ключей, ячейки, правила, дверь |
| `split` | Счётная комната: стартовый расклад, готовые расклады, предел получателей, подпись в углу листа, все подписи, текст для поста в X |
| `guide` | Все подписи и данные макета `guide`: список страниц и меню, обложка, предисловие, шкала звёзд, колонки «всем и держателям», этикетка, тарелки, издания, правила, бланк брони |
| `inspect` | Инструмент «Инспекция»: адрес функции, дневной предел, подпись на карточке, позы героя для каждой оценки, все подписи, тексты ошибок, образец рецензии, текст для поста в X |
| `boss` | Герой у края страницы, который растёт при прокрутке: спрайт, подпись, вес от и до |
| `paper` | Все подписи макета `contract`: названия разделов, приписки ручкой, мелкий шрифт, тексты подписи, слово на печати, включение приёмов (`paper.fx`) |
| `assets.heroVideo` | Короткое видео без звука вместо фото на первом листе (макет `contract`) |
| `game` | Игра «выбери клетку»: поле, шансы, стикеры, реплики |
| `images` | `"optimize": true` сжимает картинки при сборке. `maxSize` — предел в пикселях для каждой подпапки |
| `effects` | Появление при прокрутке, параллакс, курсор (`cursorIcon`), искры по клику |

## Макет `contract`: сайт как документ

Сайт выглядит как стопка листов на столе. Обычные поля конфига остаются теми же, меняется только подача:

| Поле конфига | Чем становится |
|---|---|
| `tagline`, `hero.text`, `assets.hero` | Первый лист: бланк, заголовок, фото или видео на скрепке |
| `about` | Пункты договора с номерами, сбоку фото на скрепке |
| `howToBuy` | Список обязанностей с пустыми клетками |
| `tokenomics` | Ведомость: название, точки, значение |
| `gallery` | Фотографии на столе. Их можно таскать, по нажатию фото переворачивается. Поле `note` — записка на обороте |
| `roadmap` | Приказы: по одной карточке на этап, на каждой печать |
| `disclaimer` | Мелкий текст внизу, прямо на столе |

Разметка внутри текстов (`about.text`, `hero.text`, `howToBuy`, `tokenomics.items`, `paper.signText`):

- `[[текст]]` — замазанный текст, открывается при наведении или нажатии;
- `~~текст~~` — зачёркнуто красной ручкой;
- `{{текст}}` — приписка красной ручкой.

Приёмы оформления (`paper.fx`, каждый можно выключить): `stamps` — печать по клику, `pen` — приписки появляются при прокрутке, `redact` — замазанный текст, `loupe` — лупа над мелким шрифтом. Растущий герой включается секцией `bossGrow` и полем `boss`, подпись с кнопкой покупки — секцией `paperSign`.

Номера страниц «Page 2 of 7» считаются сами по порядку секций в макете.

## Макет `delivery`: сайт как приложение доставки

Сайт выглядит как экран заказа в телефоне. На узком экране страница и есть приложение. На широком посередине стоит рамка телефона, страница листается внутри неё, по бокам название и статусы заказа.

| Поле конфига | Чем становится |
|---|---|
| `tagline`, `hero`, `assets.hero` | Карточка заказа на первом экране: картинка, название, тикер, слоган, записка от курьера |
| `about` | Профиль курьера: фото, имя, оценка, три цифры и список фактов |
| `howToBuy` | Оформление заказа по шагам |
| `tokenomics` | Чек: строки с точками, общее количество как итог, адрес контракта и штрихкод |
| `gallery` | Истории: полоски сверху, касание листает, на каждом фото штамп. Поле `note` — комментарий курьера |
| `roadmap` | Список будущих заказов, у каждого плашка статуса из `app.next.statuses` |
| `disclaimer` | Мелкий текст в самом низу |

Что задаётся в `app`:

- `statuses` — статусы заказа. У каждого `label` и `at` (id раздела: `home`, `map`, `courier`, `chat`, `game`, `rate`, `how-to-buy`, `receipt`, `reports`, `next`, `order`). Статус в верхней строке меняется, когда раздел доходит до середины экрана.
- `pushes` — уведомления. Каждое выпадает сверху один раз, когда его раздел (`at`) появляется на экране.
- `tabs` — нижнее меню: `id` раздела, подпись и значок (`order`, `map`, `chat`, `game`, `pay`).
- `map` — карта: метка курьера едет по маршруту прочь от дома, пока страница листается. `etas` — список сроков по порядку, `from` и `to` — расстояние в начале и в конце.
- `chat` — чат: `intro` (первые сообщения) и `replies` (готовые фразы посетителя и ответы курьера по очереди). Ответ `photo` присылает картинку из `chat.photo`, ответ с `sys:` в начале выглядит как серая служебная строка.
- `rate` — оценка: посетитель ставит звезду, в ответ появляется оценка от курьера (`courierStars`) и его комментарий.
- `order` — покупка: кнопка открывается, когда посетитель дотянул ползунок до конца. Для клавиатуры работают Enter и пробел, под ползунком есть обычная ссылка.
- `side` — боковые панели на широком экране: подписи и картинка героя.

## Макет `press`: сайт как печатный станок

Вся страница — один станок, посетитель — лист бумаги, который через него едет. Работает с темой `riso`.

| Поле конфига | Чем становится |
|---|---|
| `tagline`, `hero`, `assets.hero` | Первый лист: тикер, название, слоган, две кнопки и картинка, которая печатается в два слоя |
| `about` | Карточка героя: картинка, текст, три цифры (`press.about.stats`) и цитата |
| `studio` | Станок для мемов (см. ниже) |
| `howToBuy` | План тренировки: по карточке на шаг, галочка ставится сама, когда карточка дошла до середины экрана, или по нажатию |
| `tokenomics` | Картриджи с краской: по одному на строку, уровень в процентах берётся из `press.ink.levels`. Количество токенов — «общий тираж», под ним адрес контракта |
| `gallery` | Сушка тиража: листы висят на верёвке на прищепках, качаются при прокрутке, лента листается вбок. Поле `note` — подпись под листом. Кнопка под листом отправляет картинку в станок |
| `roadmap` | Расписание смен: по карточке на этап, часы и статус из `press.shifts`, в конце зачёркнутый выходной |
| `disclaimer` | Мелкий текст в самом низу |

Что задаётся в `press`:

- `nav` — пункты меню в шапке: `id` раздела и подпись. Id разделов: `home`, `coach`, `studio`, `how-to-buy`, `ink`, `prints`, `shifts`, `buy`.
- `counter` — счётчик тиража в шапке: подпись, с какого числа начинать, сколько пикселей прокрутки дают один лист, сколько листов добавляет простой.
- `statuses` — этапы пути листа. У каждого `label` и `at` (id раздела). Этап меняется, когда раздел доходит до середины экрана. На широком экране это рейка слева, на узком — строка под шапкой.
- `coach` — тренер: если посетитель ничего не делает `idleSeconds` секунд, снизу выезжает одна из реплик `lines`. `{n}` в реплике заменяется на число листов.
- `ink`, `line`, `shifts`, `buy`, `workout`, `hero`, `about`, `footer` — подписи соответствующих разделов.
- `buy` — кнопку покупки надо держать нажатой, пока лист с ней не выедет целиком. С клавиатуры хватает Enter или пробела, под кнопкой есть ссылка «напечатать без удержания».

Приёмы оформления встроены в секции: картинки печатаются в два слоя (компонент `RpPrint`), заголовки разделов держит рука из-за края экрана (компонент `RpTitle`).

Адрес контракта показывается в двух местах: под картриджами и на напечатанном листе с кнопкой покупки.

### Станок для мемов (`studio`)

Работает целиком в браузере, картинки посетителя никуда не отправляются.

- `templates` — готовые основы, квадратные картинки. Удобно брать сцены из галереи.
- `stickers` — наклейки с прозрачным фоном. Первые `freeStickers` открыты всем, остальные помечены замком и открываются переключателем «для держателей».
- `watermark` — подпись в углу листа. При включённом переключателе «для держателей» её нет.
- Фильтр «оттиск в две краски» сам включается для своей картинки посетителя. Готовые основы показываются как есть: они уже нарисованы как оттиск. Посетитель может переключить режим вручную, тогда его выбор сохраняется.
- `inks` — цвета красок фильтра. Если не задавать, берутся цвета темы: `primary`, `secondary`, `accent` на фоне `bg`.
- `labels` — все подписи кнопок и полей, `shareText` — текст для поста в X.

Переключатель «для держателей» — это показ: он открывает третью краску и все наклейки без проверки кошелька. Настоящая проверка баланса появится только вместе с адресом контракта.

Кнопка «Поделиться»: на телефоне открывается системное меню, в которое передаётся сама картинка. На компьютере открывается X с готовым текстом, картинку надо приложить вручную — ссылка X не умеет прикладывать файл.

На узком экране станок закреплён под шапкой, пока посетитель листает настройки. Напечатанный лист появляется под кнопкой печати и убирается, как только посетитель снова что-то меняет.

## Макет `vault`: сайт как дверь на десять замков

Вся страница — дверь хранилища. Каждый раздел — замок: он открывается, когда посетитель до него дошёл, и остаётся открытым. Работает с темой `concrete`.

| Поле конфига | Чем становится |
|---|---|

Что задаётся в `vault`:

- `locks` — список замков по порядку: `id` раздела, подпись и, если раздел нужен в меню шапки, поле `nav` с коротким названием. Id разделов: `home`, `why`, `split`, `holders`, `how-to-buy`, `keys`, `cells`, `plan`, `rules`, `door`. Номер замка раздел берёт из своего места в этом списке.
- `status` — строка состояния внизу экрана: `start` (до первой прокрутки), `line` (шаблон с `{n}` и `{left}`), `last` (когда открыты все замки). Разделы на несколько секунд занимают строку своими сообщениями: счётная комната пишет сумму, ячейки — номер открытой ячейки.
- `bar`, `plate`, `railTitle` — подписи шапки, таблички замка и большого циферблата.
- `hero`, `why`, `holders`, `steps`, `rack`, `cells`, `plan`, `rules`, `door`, `footer` — подписи разделов.

Приёмы оформления встроены в секции:

- Счётчик замков в шапке растёт по мере прокрутки, цифры прокручиваются, как на механическом счётчике (компонент `VkOdo`, им же набраны крупные цифры в разделах).
- Циферблат замка поворачивается вместе с прокруткой: маленький в шапке, большой справа на экранах от 1440 пикселей.
- Чертежи на фоне разделов прорисовываются линией при появлении (компонент `VkDraw`: `door`, `key`, `split`, `cells`, `lock`).
- Правило одного сигнала: на каждом экране один предмет цвета `accent`. Поэтому основные кнопки тёмные, а сигнальным цветом отмечены по одному элементу на раздел (поле `signal` у цифры и у колонки, последний шаг покупки, десятый ключ, метка «сейчас», знак у дисклеймера, ключ в двери).
- Дверь: на каждый открытый замок убирается один засов. Когда открыты все, посетитель поворачивает ключ, штурвал прокручивается, дверь распахивается, за ней кнопка покупки. С клавиатуры работает кнопка «повернуть ключ», под ней есть ссылка, которая открывает дверь сразу.

Адрес контракта показывается в двух местах: под стойкой ключей и рядом с открытой дверью.

### Счётная комната (`split`)

Калькулятор дележа комиссии создателя. Работает целиком в браузере: ничего не отправляется и не сохраняется, кошелёк не подключается.

- `start` — расклад, с которым страница открывается: роль и доля в процентах.
- `presets` — готовые расклады одной кнопкой. `"mode": "equal"` делит 100% поровну между уже имеющимися строками, остаток в сотых долях уходит первым ключам. Расклад с `rows` заменяет роли и доли, кошельки по номерам строк остаются.
- `max` — предел получателей, по умолчанию 10.
- Проверки: сумма ровно 100%, получателей не больше предела, нет нулевых долей, кошельки похожи на адрес Solana, кошелёк не повторяется. Пока хоть одна не пройдена, кнопка «запечатать» выключена, а под ней словами написана причина с номерами ключей (подписи `whySum`, `whyCount`, `whyPositive`, `whyWallets`, `whyUnique`).
- Доли хранятся в сотых долях процента, поэтому 33,34 + 33,33 + 33,33 дают ровно 100. Десятичный знак можно вводить точкой и запятой.
- «Запечатать» рисует лист на canvas 1200×1500 и считает код печати из содержимого: одинаковое содержимое даёт одинаковый код, так два человека сверяют, что держат один и тот же лист. Лист скачивается как PNG, рядом кнопка «скопировать текст» для чата команды (в тексте кошельки целиком, на картинке сокращённо) и кнопка поста в X.
- После любой правки лист помечается как устаревший, запечатывать нужно заново.
- `watermark` — подпись в углу листа. При включённом переключателе «для держателей» её нет.
- `labels` — все подписи, `shareText` — текст для поста в X (`{n}`, `{max}`, `{code}`).

Переключатель «для держателей» — это показ: он убирает подпись с листа и открывает сравнение двух раскладов и выгрузку таблицей без проверки кошелька. На сайте это сказано прямо.

Инструмент не назначает и не переводит комиссии: доли выставляются на pump.fun. Лист не является договором, это тоже написано на сайте и на самом листе.

## Макет `guide`: сайт как ресторанный гид

Вся страница — печатный гид, разделы — его страницы. Список страниц задаётся в `guide.pages`: `id` раздела, название, значок для меню (`star`, `cloche`, `knife`, `fork`, `plate`, `book`, `bill`, `door`) и `"nav": true` для тех, что попадают в меню. Номер страницы раздел берёт из своего места в списке.

Приёмы оформления:

- Обложка гида вместо первого экрана: строка издания со звёздами, имя, тикер, слоган, главная картинка целиком (16:9) и три коротких факта (`guide.cover`). Необязательное `guide.cover.background` — цвет фона главной картинки: обложка красится им, и картинка сливается с ней без рамки.
- Меню из значков гида; пункт подсвечивается, когда раздел на экране. В углу экрана метка «стр. N из M» с названием страницы.
- Шкала звёзд (`guide.stars.rows`): шесть строк от нуля до пяти, звёзды строки загораются по одной, когда строка появляется на экране. У каждой оценки своя поза героя из `inspect.poses`.
- Блокнот инспектора: шаги агента появляются записями, пока он работает; последняя запись мигает.
- Результат свёрстан как карточка заведения: звёзды, «кухня», «средний чек», «часы работы», «блюдо дня», цитата, строка фактов.
- Токеномика — этикетка «состав» с толстыми линейками (`guide.label`), рядом адрес контракта.
- «Как купить» — четыре подачи (`guide.book.courses` даёт подписи над шагами).
- Галерея — тарелки на тёмном столе с карточками-подписями; нажатие открывает картинку целиком (`gallery[].note` — подпись).
- Кнопка покупки — бланк брони (`guide.reserve`): два ряда вариантов, кнопка «подтвердить», после неё штамп, ссылка на покупку и адрес контракта. Под бланком всегда есть обычная ссылка.

Id разделов: `home`, `about`, `stars`, `inspect`, `token`, `how-to-buy`, `label`, `plates`, `editions`, `rules`, `reserve`.

Адрес контракта показывается в двух местах: рядом с этикеткой и на бланке брони.

Простые числа (номера шагов и правил, цифры на карточке, доли) набраны шрифтом текста: в шрифте заголовков Fraunces тройка с плоским верхом читается как пятёрка.

### Инспекция (`inspect`) и серверная функция

Это первый инструмент шаблона, которому нужен сервер: ключ языковой модели нельзя держать в браузере.

- Страница: секция `guideInspect`. Посетитель вставляет адрес кошелька Solana, кошелёк не подключается.
- Сервер: `templates/landing/api/inspect.js` — функция Vercel. Она лежит рядом с сайтом и публикуется вместе с ним; старые сайты репозитория получают ту же функцию, но она отвечает «не найдено» всем проектам, для которых в `api/_agent/persona.js` нет характера агента (проект определяется той же переменной `PROJECT`).
- Агент (`api/_agent/agent.js`): модель сама решает, какой инструмент вызвать. Инструментов три: `read_trades` (последние транзакции кошелька → торговые факты), `look_up_token` (сведения о токене с DexScreener, не больше четырёх раз) и `file_review` (сдать рецензию). Не больше шести ходов; на последнем рецензия требуется принудительно. Неполная рецензия (модель пропустила поля или ей не хватило места) один раз возвращается на доработку; если пробелы остались, они дописываются простыми фразами из фактов, так что карточка не бывает полупустой.
- Факты (`api/_agent/facts.js`) считает код, а не модель: число обменов, доля позиций, проданных дороже покупки, итог в SOL, «мешки на плите», самая быстрая перепродажа, часы активности. Цифры на карточке всегда из этого расчёта.
- Данные о сделках (`api/_agent/chain.js`): сначала разобранная история Helius (один запрос на 100 транзакций, до двух страниц), при отказе — обычные запросы к узлу Solana (до 48 транзакций).
- Ответ идёт потоком строк JSON: `step` (что сделал сервер), `note` (реплика агента), `facts`, `review`, `error` (короткий код), `done`.
- Названия токенов пишет кто угодно, поэтому до модели и до страницы они доходят урезанными до латиницы, цифр и 12 знаков; модель видит короткие номера `T1…T8`, а не адреса.

Переменные окружения проекта на Vercel (Settings → Environment Variables):

| Переменная | Зачем |
|---|---|
| `PROJECT` | имя проекта, как для сайта |
| `LLM_API_KEY` | ключ API языковой модели (обязательна) |
| `HELIUS_API_KEY` | ключ Helius для чтения сделок (обязательна, если нет `SOLANA_RPC_URL`) |
| `SOLANA_RPC_URL` | необязательно: адрес любого узла Solana вместо разобранной истории |
| `LLM_MODEL` | необязательно: модель, по умолчанию `claude-haiku-4-5-20251001` |
| `AGENT_PER_IP` | необязательно: инспекций в день на посетителя, по умолчанию 5 |
| `AGENT_DAILY_CAP` | необязательно: инспекций в день на весь сайт, по умолчанию 300 |

Ключи в репозиторий и в чат не попадают. Главный предохранитель расходов — лимит трат, выставленный в кабинете поставщика модели: счётчики функции живут в памяти и сбрасываются при перезапуске.

Что видит посетитель, когда агент недоступен:

- локальный просмотр (`npm run dev`) функцию не запускает: кнопка «Inspect» выключена, под ней написана причина, работает образец;
- функция есть, но ключей нет — то же самое;
- образец (`inspect.sample`) — выдуманный кошелёк, на карточке и на картинке стоит пометка «Sample entry. Invented wallet.».

Поля `inspect`:

- `poses` — шесть картинок героя с прозрачным фоном, по номеру оценки от 0 до 5;
- `perDay` — сколько инспекций в день помнит браузер посетителя (по умолчанию 3);
- `watermark` — подпись в углу карточки; при включённом переключателе «для держателей» её нет;
- `labels`, `errors` — все подписи и тексты ошибок; `shareText` — текст для поста в X (`{stars}`, `{quote}`, `{url}`).

Переключатель «для держателей» — это показ: он открывает полную рецензию (три абзаца вместо одного), сравнение двух кошельков и карточку без подписи, кошелёк не проверяет. На сайте это сказано прямо.

Проверка без ключей: в облаке или на компьютере агент прогоняется на подставных ответах внешних сервисов (обычный путь, рецензия по принуждению, пустой кошелёк, запасной путь через узел, отказ модели, лимиты). Настоящий путь проверяется только на опубликованном сайте с ключами.

## Макет `wheel`: сайт как колесо зодиака

Первый экран — колесо из двенадцати знаков, в центре герой. Знак выбирают один раз: нажатием на знак, стрелками, перетаскиванием колеса или по дню рождения. Выбор запоминается в браузере, и вся страница его слушается (`window.wh.setSign`): значок в шапке, запись в выпуске, карточка.

Приёмы оформления:

- Фон-аура закреплён позади страницы и меняет цвета по мере прокрутки: от ночи наверху к рассвету внизу. Четыре опорные точки заданы в коде, свои можно дать в `wheel.sky` (`[{ "at": 0…1, "c": ["#…", "#…", "#…"] }]`). Звёзды гаснут к низу страницы.
- Знак в шапке: тёмная плашка с глифом выбранного знака, до выбора — «Pick a sign».
- Знак по дню рождения (`wheel.hero.birthLabel`): два списка, день и месяц. Дата остаётся в браузере.
- Запись выходит из тумана: карточку записи закрывает туман, он рассеивается, и текст печатается по буквам.
- Планета дня и кнопка «свалить на неё»: падающая звезда и счётчик, который хранится в браузере.
- Токеномика — созвездие (`wheel.stars`): звёзды зажигаются по одной, линия между ними измеряется по настоящим местам звёзд и поэтому идёт за любой раскладкой.
- «Как купить» — четыре фазы луны (`wheel.moons.phases` даёт названия фаз).
- Архив — лунный календарь (`wheel.calendar`): четыре недели, у каждого дня настоящая фаза луны для этой даты. Дни с выпуском открываются; старше `issue.freeDays` показывают замок, пока не включён показ для держателей.
- Галерея — стеклянные пузыри (`wheel.bubbles`), нажатие открывает картинку целиком с подписью (`gallery[].note`).
- Кнопка покупки спрятана в шаре с туманом (`wheel.ball`): туман стирают пальцем или мышью; есть кнопка «убрать туман» для клавиатуры и обычная ссылка под шаром. Без скриптов шар чистый.

Глифы знаков нарисованы кодом (`src/lib/wheel.ts`), картинки для них не нужны. Два раздела («созвездие» и «календарь») и раздел с шаром тёмные, остальная страница светлая.

Id разделов: `home`, `today`, `madame`, `how`, `token`, `how-to-buy`, `stars`, `archive`, `gallery`, `plan`, `rules`, `ball`.

Адрес контракта показывается в двух местах: под созвездием и внутри шара.

Шрифт заголовков Bagel Fat One существует в одном начертании. Тема выключает искусственное утолщение (`font-synthesis: none`), иначе тикер выходит «жирнее жирного».

### Утренний выпуск (`issue`) и агент по расписанию

Это второй инструмент с сервером и первый, где агента никто не вызывает: он работает сам раз в сутки.

- Страница: секция `wheelIssue`. Посетитель ничего не отправляет на сервер.
- Расписание: `templates/landing/vercel.json`, одно задание Vercel Cron на `/api/issue-run` в 06:00 UTC. На бесплатном плане Vercel задание срабатывает не чаще раза в сутки и в пределах часа. Файл общий для всех сайтов репозитория, поэтому задание появляется у каждого проекта; функция отвечает «не найдено» всем проектам, для которых в `api/_agent/oracle.js` нет характера.
- Пишущая функция `api/issue-run.js`: один выпуск на день по UTC. Если сегодняшний выпуск уже есть, модель не вызывается; до часа расписания функция отвечает `early`. Адрес можно открыть руками: после часа расписания он запустит агента, если выпуска ещё нет. Перед сохранением текст проверяет код (`flawedFields` в `api/_agent/oracle.js`): поле, где названа оценка, есть совет или слова о будущем, либо запись знака не называет планету из расклада, один раз возвращается модели на переписывание; если поле не прошло и во второй раз, вместо него ставится простая фраза из цифр. При сбое ответ несёт короткий код `error` (`busy`, `model`, `market`, `storage`, `failed`) и уточнение `detail` (например `http_401_authentication_error`, `never_filed`, `TimeoutError`); слова поставщика модели об отказе пишутся только в журнал функции (Vercel → Logs), ключи в ответ и в журнал не попадают.
- Читающая функция `api/issue.js`: `GET` отдаёт `{ live, build, hour, issues }`, ответ кэшируется на краю на 10 минут.
- Агент (`api/_agent/oracle.js`): модель сама выбирает чтения. Инструментов четыре: `read_sky` (рынок: SOL за сутки, сколько токенов зелёных и красных; настоящее небо дня; карта дня с причиной для каждого знака), `read_movers` (главные победители, проигравшие и самые торгуемые), `read_newborns` (самые новые токены) и `file_issue` (сдать выпуск: заголовок, две фразы о небе, двенадцать записей, последняя строка — все поля плоские). Не больше шести ходов. Выпуск нельзя сдать, не прочитав небо и хотя бы одно другое чтение. Неполный выпуск один раз возвращается на доработку; оставшиеся пробелы дописываются простыми фразами из чисел. Если модель так и не сдала выпуск, он не публикуется: на сайте остаётся вчерашний.
- Числа рынка (`api/_agent/market.js`) считает код.
- Небо настоящее (`api/_agent/sky.js`): на момент запуска код считает, в каком знаке стоят Солнце, Луна и восемь планет, кто ретрограден и какая фаза у Луны. Формулы упрощённые (элементы орбит с линейным ходом, главные члены долготы Луны), точность — доли градуса для 1800–2050 годов. Из этого неба рисуется карта дня: для каждого знака складываются влияния тел, которые стоят в знаке, напротив, в квадрате, тригоне или секстиле к нему, отдельно учитывается ретроградный управитель знака. Оценка из 10 — это сумма, сдвинутая настроением рынка. Планета-виновник — та, что отнимает у знака больше всех, и к ней прилагается причина одной фразой («Saturn is retrograde in Aries, opposite your sign»). Планета дня: ретроградные Меркурий, Венера или Марс; иначе новолуние или полнолуние; иначе планета, с которой Луна сегодня точнее всего соединяется, стоит в квадрате или в оппозиции. Ничего случайного нет: одна дата даёт одно небо и одну карту. Модель пишет только слова и не может двигать планеты.
- В выпуске сохраняются `sky_now` (десять строк неба, фаза Луны, список ретроградных), `planet_why` и `why` у каждого знака; страница показывает их рядом с текстом, а карточка-картинка печатает причину под оценкой.
- Данные: тренды и новые пулы GeckoTerminal, цена SOL и запасной список токенов с DexScreener. Ключи не нужны.
- Названия токенов не читаются вовсе: модель получает номера `T1…` и числа. Из текста модели вычищаются знак `$` перед буквами, ссылки и строки, похожие на адреса.
- Журнал (`api/_agent/journal.js`): один файл `<проект>/journal.json` в Vercel Blob, до 90 выпусков, одна запись в сутки. Перед первым выпуском пишется пустой файл: если хранилище не работает, модель не вызывается. Повреждённый файл не перезаписывается.

Переменные окружения проекта на Vercel:

| Переменная | Зачем |
|---|---|
| `PROJECT` | имя проекта, как для сайта |
| `LLM_API_KEY` | ключ API языковой модели (обязательна) |
| `BLOB_READ_WRITE_TOKEN` | появляется сама, когда к проекту подключают хранилище Blob (Storage → Blob) |
| `BLOB_ACCESS` | необязательно: `private`, если хранилище создано закрытым; по умолчанию ожидается открытое |
| `CRON_SECRET` | необязательно: тогда функция записи отвечает только на вызовы с этим секретом (Vercel подставляет его сам), а с `?key=…` её можно запустить до часа расписания и с `&force=1` переписать сегодняшний выпуск |
| `ISSUE_HOUR_UTC` | необязательно: час расписания, по умолчанию 6; должен совпадать с `vercel.json` |
| `LLM_MODEL` | необязательно: модель, по умолчанию `claude-haiku-4-5-20251001` |

Что видит посетитель, когда агента нет: локальный просмотр и сайт без ключей показывают образец из `issue.sample` с пометкой «Sample», датированный сегодняшним числом. Образец имеет ту же форму, что и сохранённый выпуск.

Поля `issue`:

- `poses` — три картинки героя с прозрачным фоном: `low` (оценка 1–3), `mid` (4–7), `high` (8–10); `oracle` — картинка до выбора знака;
- `freeDays` — сколько дней архива открыто всем (по умолчанию 7);
- `watermark` — подпись в углу карточки; при включённом показе для держателей её нет;
- `compat` — фразы совместимости двух знаков по сумме их оценок (`{a}` и `{b}` — планеты);
- `labels` — все подписи; `shareText` — текст для поста в X (`{sign}`, `{score}`, `{planet}`).

Показ для держателей — это переключатель: чистая карточка, совместимость двух знаков, весь архив. Кошелёк он не проверяет, на сайте это сказано прямо.

Проверка без ключей: `node tests/issue.test.mjs` в `templates/landing` — одиннадцать сценариев: десять на подставных ответах (обычный путь, один выпуск в день, рост архива, час расписания и секрет, доработка и дописывание, порядок чтений и чистка текста, отказы модели, запасной источник данных, защита хранилища, читающая функция) и сверка неба с календарём (эпоха J2000, равноденствие 2026 года, затмения 08.04.2024 и 14.03.2025, новолуние и полнолуние осени 2026 года, ретроградные Меркурий и Венера 2026 года, знаки планет на 07.10.2026). Настоящий путь проверяется только на опубликованном сайте с ключом и хранилищем.

## Правила, набитые на первых проектах

- **Анимация 16:9 делается только из исходника 16:9**, вертикальная — из 9:16. Из квадрата выходит квадратное видео.
- **Для анимации герой должен быть крупным**, в середине кадра. Из сцены, где герой мелкий, генератор сам приближает камеру и перерисовывает героя по-своему. Движение просить простое, камеру неподвижную. Конец ролика проверять по кадрам и обрезать, если герой «поплыл».
- **Видео для сайта — отдельный лёгкий файл** без звука (960×540, до 1 МБ). Полный ролик 1080p остаётся для pump.fun и X.
- **Баннер во Flow — 16:9**, формата 3:1 там нет. Героев держать небольшими и в нижней части кадра, тогда обрезка до 1500×500 в Figma проходит без потерь.
- **Текст на картинках — белый с тёмной обводкой.** Цветной текст на пёстром фоне не читается.
- **В галерее только квадратные сцены и логотип.** Широкая картинка ломает ритм ленты.
- **Всё, что лежит в `brand/`, кроме `docs/` и файлов `_raw`, публикуется на сайте.** Черновики, архивы и картинки, которые не должны быть публичными, класть в `docs/`.
- **Чужие бренды и персонажи на картинках.** Генератор может сам дорисовать плакаты, логотипы или технику известных марок. Такие картинки перед публикацией проверять и переделывать.
- **Имена файлов на GitHub чувствительны к регистру**, в Windows — нет. Расширения сверять.
- **Запятые в JSON.** Лишняя или пропущенная запятая ломает сборку: смотреть вкладку PROBLEMS в VS Code.
- **Проверять на двух ширинах:** компьютер и телефон. Длинные слова и числа в пиксельном шрифте занимают много места.
- **На сайте и в постах нет обещаний прибыли**, внизу страницы обязателен дисклеймер.

## Когда всё-таки нужен код

- **Новая секция:** создать файл в `src/sections/`, зарегистрировать в `src/pages/index.astro`, добавить имя в макет.
- **Новый инструмент вместо игры:** отдельная секция по образцу `press/PressStudio.astro` или `vault/VaultSplit.astro`. У секции должен быть тестовый хук, которым проверка проходит все действия.
- **Новая игра:** отдельная секция по образцу `ChaseGame.astro` или `paper/FeedGame.astro`. Тексты и картинки брать из конфига, цвета из темы.
- **Новый характер оформления:** блок правил `.flavor-<имя>` в `src/styles/global.css`.
- **После добавления стилей** страницы старых проектов остаются прежними, меняется только имя общего файла стилей в ссылке (у него новый хэш).
- **Новый макет с собственными секциями:** секции класть в отдельную подпапку `src/sections/<макет>/`, эффекты подключать отдельной секцией (как `paperFx`), а не через общий `Effects.astro`. Тогда страницы старых проектов не меняются ни на байт.

После любой правки шаблона пересобрать все существующие проекты и убедиться, что они выглядят как раньше.

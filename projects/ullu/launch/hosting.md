# Ullu — переезд с Vercel на хостинг заказчика

Черновик 05.11.2026. Vercel — первая ступень. Потом заказчик арендует свой хостинг, даёт доступ, и мы переносим сайт к нему. Сайт с самого начала собран так, чтобы переезд не требовал переделок.

## Что уже сделано для переезда

- Сайт — готовые страницы плюс две маленькие серверные функции: `/api/street` (улица домов) и `/api/geo` (страна и город посетителя). Функция написана по общему стандарту веба и одинаково работает на Vercel и на обычном сервере.
- Хранилище улицы переключается настройкой. На Vercel это Vercel Blob. На своём сервере — обычный файл на диске (`STORE=file`, `DATA_DIR=папка`). Одновременные записи не теряются, это проверено тестом.
- Для теста на Vercel лучше создать Blob-хранилище с доступом **Private** и добавить в проект настройку `BLOB_ACCESS=private`. Тогда файл улицы никто не скачает по прямой ссылке, а сервер всегда читает свежую версию. Публичное хранилище отдаёт файл через CDN с задержкой до минуты; на этот случай сервер помнит свою последнюю запись, но на нескольких копиях функции сразу это не полная защита.
- Служба systemd из README запускается с защитой: писать она может только в папку данных, остальная система для неё только для чтения. Файл `.env` с солью закрыт правами `600`, в образ Docker он не попадает (`.dockerignore`).
- Свой маленький веб-сервер `templates/landing/server/serve.mjs`: отдаёт страницы и запускает функции. Нужен только Node 20 или новее.
- Упаковка: `node scripts/pack-site.mjs` собирает папку `templates/landing/release/ullu/`. В ней только Ullu, без кода других проектов: страницы, функция, сервер, `package.json`, пример настроек `.env.example`, `Dockerfile` и инструкция для админа заказчика на английском (`README.md`).
- Все дома индийские (пять улиц). Улицу посетитель выбирает сам на первом заходе; город для таблички приходит от `/api/geo`, а если хостинг его не передаёт — табличка просто без города.
- Адрес посетителя (для лимита публикаций) сервер берёт из заголовка `X-Forwarded-For` только если запрос пришёл от прокси на этой же машине или из внутренней сети (nginx перед сервером, Docker). Если сервер открыт в интернет напрямую, заголовок игнорируется. Настройка `TRUST_PROXY`: пусто — так, как описано; `1` — верить всегда (прокси на другой машине с внешним адресом); `0` — не верить никогда.

Проверено в облаке 05.11.2026: упакованная папка запущена своим сервером с хранением в файле, весь сайт прогнан — дом, семь ночей, карточка, улица, картинка.

## Домен

Сначала всё тестируем на Vercel, потом отдаём сайт на домен заказчика, и полноценная работа начинается уже там (решение 05.11.2026). Тестовые дома на адресе Vercel туда не переедут: это нормально, на тесте живых посетителей нет. `STREET_SALT` на сервере заказчика задаём один раз при запуске и больше не меняем.

## Что нужно от заказчика

1. **Сервер.** VPS на Linux (Ubuntu 22.04 или 24.04): 1 ядро, 1 ГБ памяти, 10 ГБ диска — с запасом. Обычный «хостинг для сайтов» только с PHP не подойдёт: страницы откроются, но улица домов работать не будет. Подойдёт и хостинг, который запускает Docker или Node-приложения.
2. **Доступ.** IP-адрес и вход по SSH-ключу для пользователя с правами sudo. Ключи и пароли не присылать в чат и не класть в репозиторий.
3. **Домен** и доступ к его DNS (или пусть они сами поставят запись A на IP сервера).

## Как пройдёт переезд

1. У себя: `set PROJECT=ullu&& npm run build`, затем `node scripts/pack-site.mjs`.
2. Скопировать `release/ullu` на сервер (например, в `/srv/ullu`).
3. На сервере: `npm install --omit=dev`, затем скопировать `.env.example` в `.env` и заполнить его (`STORE=file`, `DATA_DIR=/var/lib/ullu`, новый длинный случайный `STREET_SALT`).
4. Улица на сервере заказчика начинается пустой (тестовые дома с Vercel не переносим). `DATA_DIR` должна быть папкой, куда сервер может писать.
5. Запустить как службу (systemd) и поставить nginx с HTTPS (certbot) и GeoIP2 (раздел выше). Готовые примеры — в `README.md` внутри папки.
6. Проверить сайт на сервере, потом переключить DNS домена на сервер.

Anthropic API и другие ключи ИИ сайту не нужны.

## Город посетителя (`/api/geo`)

При первом заходе сайт один раз спрашивает у сервера страну и город. По ним он предлагает стиль улицы и пишет город на карточке. Сервер ничего не хранит, город остаётся в браузере.

- **Vercel:** работает сам, ничего настраивать не надо.
- **Cloudflare перед сервером:** страну Cloudflare передаёт сам. Город — если в Cloudflare включить заголовки местоположения посетителя (Add visitor location headers).
- **Свой сервер с nginx:** нужен модуль GeoIP2 и бесплатная база городов (MaxMind GeoLite2 City или DB-IP Lite). nginx кладёт страну и город в заголовки `X-Geo-Country` и `X-Geo-City`:

```
geoip2 /usr/share/GeoIP/GeoLite2-City.mmdb {
  $geo_country country iso_code;
  $geo_city city names en;
}
location /api/ {
  proxy_pass http://127.0.0.1:3000;
  proxy_set_header X-Geo-Country $geo_country;
  proxy_set_header X-Geo-City $geo_city;
  proxy_set_header X-Forwarded-For $remote_addr;
}
```

- **Любые свои заголовки:** их имена задаются в `.env` как `GEO_COUNTRY_HEADER` и `GEO_CITY_HEADER`.

Если ничего из этого нет, сайт берёт часовой пояс браузера: стиль улицы всё равно подбирается, просто город на карточке не пишется.
